# 26 West Sport

Single-page marketing site for 26 West Sport. Built with Vite, React 18, TypeScript and Tailwind CSS (with a few shadcn/ui primitives in `src/components/ui/`).

## Development

```sh
npm ci
npm run dev       # http://localhost:8080
npm run posts     # refresh the LinkedIn post snapshot (also runs before every build)
npm run build     # outputs static site to dist/
npm run preview   # serve dist/ locally
npm run lint
```

## Configuration

Build-time variables (read via `import.meta.env`):

| Variable | Purpose |
|---|---|
| `VITE_LINKEDIN_PROFILE_URL` | LinkedIn profile: target of the "Follow on LinkedIn" button, and where the latest posts are read from |
| `VITE_LINKEDIN_POST_COUNT` | How many latest posts to show (default 3) |
| `VITE_LINKEDIN_POST_URNS` | Optional. Comma-separated post URNs to pin instead of showing the latest posts |

The Insights cards are built from `src/data/linkedin-posts.json`, generated by `scripts/fetch-linkedin-posts.mjs` before every build (or manually with `npm run posts`):

- If `VITE_LINKEDIN_POST_URNS` is empty, it reads the public (logged-out) profile page, takes the newest posts the profile authored itself (not likes or reposts) and snapshots their title, excerpt, cover image and date.
- If it's set, exactly those posts are used.
- The deploy workflow runs daily, so new posts appear on the live site within a day without any changes.

The public profile page isn't an official LinkedIn API, so it can change or show a login wall. Any failure keeps the previously saved posts, so builds never break. Commit `src/data/linkedin-posts.json` whenever it changes so that fallback stays fresh.

Locally, put them in `.env.local`. For deploys, set them as GitHub Actions repository **variables** (Settings → Secrets and variables → Actions → Variables).

## Deployment

Every push to `main`, plus a daily scheduled run (06:00 UTC) and manual runs from the Actions tab, builds the site and publishes `dist/` to the `gh-pages` branch via `.github/workflows/gh-pages.yml`.
